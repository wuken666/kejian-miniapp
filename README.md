# 课见 · 教师 AI 助手（微信小程序）

这是独立的微信小程序仓库，通过网络接口连接独立部署的 Java 后端和语音识别服务。仓库不包含后端源码、数据库或录音数据。

课表支持课程新建、改期、请假、取消和签到；从已签到课程进入录音页时会带入学生与课程信息。签到状态由老师确认。

## 本地导入

1. 启动 MySQL、FunASR 和 Java 后端。
2. 在微信开发者工具中导入本仓库根目录。
3. `project.config.json` 已配置正式 AppID，并关闭开发阶段域名校验。
4. 本机调试默认连接 `http://127.0.0.1:8080/api` 和 `ws://127.0.0.1:8090/ws/transcribe`。
5. 在本机 `service-config.local.js` 中配置实际服务地址，重新编译小程序。该文件和微信开发者工具的个人设置不会提交到 Git。

首次配置时，可复制 `service-config.example.js` 为 `service-config.local.js`，手工填写 HTTPS 域名。也可以临时在开发者工具控制台执行：

```js
wx.setStorageSync('keban-api-base-url', 'https://你的域名/api')
wx.setStorageSync('keban-asr-ws-url', 'wss://你的域名/asr-stream')
```

开发版若设置了 `developmentHost`，优先使用该局域网地址；否则使用本地存储或配置中的服务地址。更换网络后应核对地址并重新编译。

## 微信登录与数据隔离

小程序正式环境使用 `wx.login()` 换取课伴登录令牌，后端再用微信 `AppID + AppSecret` 换取 `openid`。学生、课堂、录音、反馈和客户端异常都从服务端当前登录老师取得归属，前端不提交 `teacherId` 作为权限依据。

后端启动时设置以下环境变量：

```text
WECHAT_APP_ID=小程序 AppID
WECHAT_APP_SECRET=只放在后端环境变量中的 AppSecret
AUTH_REQUIRE_TEACHER_TOKEN=true
WECHAT_SESSION_TTL_HOURS=168
```

数据库会由 Flyway 自动执行 `V17__create_teacher_auth_tables.sql`，建立微信身份绑定和令牌会话表。`AUTH_REQUIRE_TEACHER_TOKEN=false` 只用于本地单老师联调；正式公网环境不能依赖默认老师 `id=1`。

小程序本地配置 `service-config.local.js` 中将 `wechatAuthEnabled` 设为 `true` 后，启动时会自动调用微信登录；开发者工具本地联调可以保持 `false`，此时业务请求使用后端明确配置的本地默认老师回退。

运行模式必须明确：空的 `publicOrigin` 代表本机联调；公网地址配合 `accessToken` 只代表单人临时试用；正式公网小程序必须设置 `wechatAuthEnabled: true` 并由后端启用强制老师令牌。公网地址既没有微信登录也没有试用访问凭证时，小程序会停止业务请求，不会静默使用默认老师。

正式版还有一道发布保护：小程序运行环境为 `release` 时，即使本地配置误带了公网临时令牌，只要 `wechatAuthEnabled` 没有显式设为 `true`，首页和业务请求都会停在配置门禁，不会进入单人试用或默认老师路径。开发版、体验版不受这条门禁影响，方便继续联调。

上传正式版前在本目录执行 `npm run release-check`。命令会检查 AppID、录音隐私说明、HTTPS 公网地址、微信登录开关，并拒绝临时访问令牌和 `trycloudflare.com` 临时隧道；它不会读取或打印密钥内容。本地单老师联调配置故意不能通过这道检查。

登录接口为：

- `POST /api/auth/wechat/login`
- `GET /api/auth/me`
- `POST /api/auth/logout`

个人页通过 `GET /api/system/status` 做轻量服务自检，只向老师展示课见服务和实时识别是否可用，不展示 API、ASR 地址或内部错误详情。

AppSecret、数据库密码、管理员令牌和模型密钥都不能写入小程序目录、Git 或前端请求参数。

## 微信后台配置

正式发布前，需要在小程序后台配置：

- 体验版和正式版通过原生云调用访问 `prod-d2gsk3hf522d2baba` 的 `kejian-api`，不回落云托管测试域名。须确保小程序与该云托管环境关联。
- 普通请求使用 `wx.cloud.callContainer`，录音使用云存储上传，实时字幕使用 `wx.cloud.connectContainer` 访问 Java 的鉴权转发，不直接连接 FunASR。
- 开发版保留普通 HTTP 调试方式，可通过本地配置 `cloudTransport: true` 测试原生云调用；不要将本地密钥配置提交到 Git。
- 后台需先部署云音频接口，并将 `CLOUD_STORAGE_DOWNLOAD_HOST` 设置为实际临时下载地址的主机名。存储桶保持私有。云端录音当前不会自动删除，上线前需确定保留周期。
- 关闭手机调试后验证体验版登录、学生列表、签到、录音上传、结束整理及实时字幕，再提交审核。`npm run test:cloud` 检查云调用适配，不能替代真机验收。
- 隐私保护指引：声明麦克风权限用于课堂记录和反馈生成。
- `app.json` 已开启隐私检查；小程序启动时注册隐私授权回调，首次录音会先说明录音、转写和 AI 反馈用途，老师拒绝后不会调用麦克风。
- 支持隐私授权接口的微信环境会在第一次录音前先触发隐私授权检查；用户拒绝时不会启动麦克风。正式使用前必须先在微信后台完成隐私保护指引配置。

## 录音可靠性

- 使用微信原生 `RecorderManager`，不依赖 H5 页面定时器保存音频。
- PCM 音频帧持续写入小程序用户目录；每 30 秒仅作为内部上传批次，不展示给老师。
- 暂停或结束时会封存不足 30 秒的尾音。
- 网络失败时保留本地队列，回到前台后自动重试。
- 网络恢复时先重新领取课堂写入权，再补传音频和重连实时字幕，避免断网超过后端租约后上传反复失败。
- 多次触发上传时共享同一个串行任务，网络恢复后不会漏掉仍在本地的分片。
- 正式微信登录令牌过期时，音频上传会自动刷新登录态并只重试一次；仍失败的片段继续留在本地队列，不会静默丢失。
- 图片识别上传也复用同样的令牌续期策略；登录态过期时只自动重试一次，避免辅助入口在长时间使用后突然失效。
- 单次原生录音在 9 分钟时自动无感续录，避开微信 10 分钟上限。
- 微信偶发不返回停止回调时，5 秒后自动封存尾音并结束保存状态。
- 新课堂会重置分片序号和实时转写，避免不同学生之间串入旧课堂内容。
- 实时字幕断开不会停止本地录音，恢复前台后重新连接。
- 记录页刷新或工作台请求短暂失败时，如果录音单例仍在采集，页面会继续保持课堂录音视图；普通加载失败提供重试入口。
- 本地 PCM 文件缺失时不会从待上传队列静默删除；系统会保留诊断元数据、停止继续采集并统一提示异常，避免页面误报“已安全保存”。

自动化测试已覆盖连续多次分段、断网后续传、暂停尾音、原生停止回调丢失、前后台恢复和跨课堂隔离。这些测试用于防止状态机回归，不能替代真机长课测试。

微信和手机系统仍可能在长时间锁屏、强制结束小程序或系统回收进程时中断麦克风。本版本会保留中断前已经落盘的音频并在下次打开时续传，但正式内测前仍需分别用 iPhone 和安卓真机做一节完整课程的切后台、锁屏和来电测试。

## 当前边界

本地默认老师回退仍保留给开发者工具联调；正式小程序交付必须打开 `AUTH_REQUIRE_TEACHER_TOKEN`，并使用真实微信 AppSecret 完成两位不同老师账号的数据隔离验收。录音可靠性自动化测试不能替代真实 iPhone 和安卓真机测试。
